# dev-rules

ChatGPT / Claude / Codex と GitHub で一人開発するときに、AIにリポジトリを壊されないための開発ルールテンプレートです。

AIにいきなりコードを書かせる前に、`docs/RULES.md` としてこのルールを置くことで、作業範囲・確認手順・記録方法を固定します。

> 月額定額AIで、無駄打ちせず、安全に一人開発を進めるための「型」です。

---

## これは何？

`dev-rules` は、AIと一緒に開発するときの事故を減らすためのテンプレート集です。

AIは便利ですが、何もルールを渡さないまま作業させると、次のようなことが起きやすくなります。

- 存在しないファイルや関数を前提にコードを書く
- 既存コードを勝手にリファクタリングする
- ついでに不要な変更まで入れる
- 会話が長くなって、前に決めたことを忘れる
- どの判断で今の実装になったのか分からなくなる
- トークンや利用枠を無駄に消費する

このリポジトリは、そうした問題を防ぐために、AIへ最初に渡す開発ルールをまとめたものです。

---

## 対象読者

このリポジトリは、次のような人向けです。

- ChatGPT / Claude / Codex を使ってアプリやツールを作ってみたい
- GitHubでプロジェクトを管理したい
- Claude Code や Codex などの高コストな使い方に頼りすぎたくない
- 月額定額AIの範囲で、できるだけ安全に開発したい
- AIにコードを書かせると、ファイル構成が壊れそうで不安
- 一人開発でも、あとから見返せるルールや判断ログを残したい

高度なチーム開発というより、まずは「一人でAI開発を始める人」のための安全柵です。

---

## できること

`dev-rules` を使うと、AIに次のようなルールを先に共有できます。

1. **コード即書き禁止**  
   いきなり実装せず、目的・リスク・方針を整理してから作業する。

2. **コード保全**  
   既存コードを勝手に削除・名前変更・大規模変更しない。

3. **ハルシネーションガード**  
   ファイルパス・関数名・設定値は、実在確認してから使う。

4. **影響範囲宣言**  
   どのファイルを変更するか、どこに影響するかを先に宣言する。

5. **スコープロック**  
   いまの作業と関係ない改善案は `BACKLOG.md` に逃がす。

6. **決定ログ**  
   なぜその設計にしたかを `DECISIONS.md` に残す。

7. **トークン節約設計**  
   毎回読む資料と、必要な時だけ読む資料を分ける。

## 最短の使い方

新しいプロジェクトで使う場合は、まず次の流れで配置します。

```text
your-project/
└─ docs/
   ├─ RULES.md
   ├─ DEVELOPMENT_PLAN.md
   ├─ DECISIONS.md
   ├─ BACKLOG.md
   └─ MODULE_INDEX.md
```

### 1. `RULES_TEMPLATE.md` をコピーする

このリポジトリの `RULES_TEMPLATE.md` を、自分のプロジェクトの `docs/RULES.md` としてコピーします。

### 2. プレースホルダーを置き換える

`{{プロジェクト名}}` や `{{日付}}` などを、自分のプロジェクトに合わせて変更します。

### 3. 管理用ドキュメントを作る

最低限、次のファイルを用意します。

- `docs/DEVELOPMENT_PLAN.md`：現在の開発計画と次にやること
- `docs/DECISIONS.md`：設計判断の記録
- `docs/BACKLOG.md`：今はやらない改善案の退避場所
- `docs/MODULE_INDEX.md`：主要ファイルや関数の所在メモ

### 4. AIに最初に読ませる

ChatGPT / Claude / Codex に作業を頼む前に、次のように伝えます。

```text
このリポジトリでは docs/RULES.md を開発ルールとして扱います。
作業前に docs/RULES.md と docs/DEVELOPMENT_PLAN.md を読んでください。
コードを書く前に、変更対象・影響範囲・確認方法を宣言してください。
```

### 5. 小さいタスクから始める

最初は、README修正、設定ファイル追加、小さな関数追加など、影響範囲が小さい作業から始めるのがおすすめです。

## AIに渡す最初の指示例

```text
このプロジェクトでは、AI開発の安全ルールとして docs/RULES.md を使います。

まず docs/RULES.md と docs/DEVELOPMENT_PLAN.md を読んでください。
そのうえで、今回の作業について以下を出してください。

1. 作業目的
2. 変更対象ファイル
3. 影響を受ける可能性があるファイル
4. 実装前の確認方法
5. テストまたは動作確認方法
6. ロールバック方法

確認が終わるまで、コードの変更はしないでください。
```

## このリポジトリの位置づけ

`dev-rules` は、特定のAIツールだけに依存するものではありません。

ChatGPT、Claude、Codex、Cursor、ターミナル型エージェントなど、使う道具が変わっても、次の考え方は共通して使えます。

- AIに丸投げしない
- 先にルールを渡す
- 作業範囲を小さくする
- 実在確認してから変更する
- 判断理由を記録する
- スコープ外の思いつきは後回しにする

AIとGitHubで一人開発を進めるための、共通の作業ルールとして育てていきます。
